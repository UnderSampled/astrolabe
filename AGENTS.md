# Astrolabe contributor guidance

## Current state

Astrolabe is being rewritten from scratch in **Rust**. The production C# source, tests, solution, and project files have been removed from the main working tree. A Rust library/CLI now implements the initial media and rooted-model slice. Read [the implementation report](./notes/implementation-progress.md) for demonstrated coverage, commands, and remaining limits; do not infer whole-level/game support from these milestones.

The previous implementations are preserved as pinned, development-only reference submodules:

- `reference/astrolabe-csharp/`: the C# worktree snapshot before the restart, including previously uncommitted work.
- `reference/astrolabe-gltf/`: the local `gltf` branch snapshot.
- `reference/BinarySerializer/` and `reference/BinarySerializer.OpenSpace/`: former C# dependencies, now research references.

Keep reference submodules unchanged unless the user requests a reference update. Their source and nested contributor instructions apply to those archived repositories, not to the Rust implementation. The archived README documents the old .NET build and CLI.

## Goals and architecture

**We MUST NOT reimplement the OpenSpace engine within Godot. Implement only the AI script API using native Godot facilities, and compile the game's AI scripts to call that API.** Preserve the API's observable gameplay behavior, not OpenSpace's internal memory, scheduler or execution machinery. This also prohibits rebuilding those internals as compiled GDScript. Use ordinary properties/references and focused Godot components. Follow [the concrete gameplay plan](./notes/godot-gameplay-plan.md): deliver actual input-driven walk/run with contact before broadening into jump, combat and magick or unrelated API coverage.

The mission is **"Make a tool to repeatably port this OpenSpace game to Godot."** Read [`docs/astrolabe/rust-architecture.md`](./docs/astrolabe/rust-architecture.md), [the Rete design](./docs/rete/rete-design.md), and [`plan.md`](./plan.md), which sets the current direction, before architecture or implementation work. They define current module boundaries, asset semantics, and ordered milestones. [`notes/historical/rete-format-csharp.md`](./notes/historical/rete-format-csharp.md), [`notes/historical/cross-package-uris-csharp.md`](./notes/historical/cross-package-uris-csharp.md), [`notes/semantic-dual-layer-framework.md`](./notes/semantic-dual-layer-framework.md), and [`notes/rete-implementation.md`](./notes/rete-implementation.md) contain historical C# requirements where they differ; the archived JSON layouts, record catalogs, build commands, and completion claims are not Rust requirements or implementation status.

Astrolabe reads **Hype: The Time Quest** OpenSpace Montreal data into one useful intermediate model with distinct **Level** and **Fix** roots. The meaningful content and relationships are the model. **Rete is its serialized form**: files representing models, materials, animations, AI scripts, scene graphs, perso families, and other real content. Direct text editing is not required. **Godot is the primary target**, including a fan-remaster and separately authored Godot content depending on locally generated original-game assets. OpenSpace reconstruction supports validation and mods to the original game; developing a new OpenSpace game is outside the scope. A full Godot-to-OpenSpace editing round trip is optional future work.

- The main architectural requirement is three separate modular I/O adapters: `openspace`, `rete`, and `godot`, composed by application code around one useful intermediate model. Keep target I/O and conversion rules in their owning module; adapters communicate through shared model/resolution contracts. Preserve these boundaries whether using one crate or several. Generic Serde derives on shared types are compatible with this design; Rete owns actual persistence. Godot export is required, while Godot import is optional future work.
- Astrolabe outputs Godot project files. Convert levels into root scenes whose subnodes mostly follow the meaningful OpenSpace hierarchy, split into instanced scenes/resources where ownership and reuse warrant it. Supported clutter, persos, parts, and initial poses must be present when the saved level opens in the editor, without a runtime loader or preview constructing them. Use native Godot nodes/resources and Animation/AnimationLibrary/AnimationPlayer tracks; resolve transform pools, sampled hierarchies, and object configurations during conversion. Compile the typed AI AST into GDScript. Do not ship JSON/table-driven asset reconstruction, a sampled-animation interpreter, or an AI AST/opcode interpreter as the port. Runtime scripts implement actual gameplay and engine semantics that require code. See [the Godot conversion contract](./docs/astrolabe/rust-architecture.md#godot-adapter-native-project-conversion).
- Use one canonical model and one implementation per concern. OpenSpace content codecs produce and consume its useful types; inspection, Rete persistence, and Godot export use those same types. Rete persistence changes the representation on disk, not the meaning or asset model. Do not require callers to load a separate OpenSpace document model before obtaining useful content.
- Assess asset boundaries, package/reference context, retained information, and the three adapters before implementing a new domain. Use both standalone media and a small level-style dependency graph to probe interfaces; record provisional decisions and their evidence before dependent features accumulate.
- The unified interface loads meaningful content files from packages into memory, then converts/saves them through supported target adapters. Keep typed context and diagnostics shared while target I/O rules stay private. A narrower OpenSpace binary-codec contract must not define the whole interface around textures/audio.
- Make binary formats **declarative by default with binrw** in the `openspace` module. Declarations document and implement how source encodings map to useful model fields in both directions. Use one typed content-codec interface for reading, writing, validation, and diagnostics so independent formats can advance together. Compose value mappings, reference resolution, and specialized algorithms through reusable helpers. Temporary headers or wire records are permitted where encoding requires them; a duplicate struct hierarchy or separate semantic conversion stage is not mandatory. Keep field meaning and source evidence connected to the declarations, and test decoded meaning plus reconstructed bytes. See [the binrw boundary and unified interface](./docs/astrolabe/rust-architecture.md#binary-codecs-with-binrw).
- Let asset ownership and sharing determine file boundaries. Use the filesystem and file/member references for lookup; load and cache whole assets on demand when useful. Do not prescribe an indexed binary container, a database, one file per engine struct, or a global file per struct kind.
- Design useful asset APIs first, then persist them with Serde and implement OpenSpace codecs. Each Rete asset is one MessagePack file, including dense arrays and raw byte buffers encoded as appropriate MessagePack values. Do not create generic binary-content sidecars. Independently shared content has its own asset file; richer texture/audio values stay inside their MessagePack assets when needed. Keep OpenSpace, Rete, and Godot adapters modular around the shared model.
- Complete useful asset slices through Godot early. A model that only reconstructs OpenSpace bytes or a script that only prints readable text is not a completed port. Check actual Godot output and behavior against source-informed expectations and Raymap, adding original-engine comparisons when feasible; engine availability is not a universal gate.
- Treat minimal OpenSpace source identity/sharing/order metadata as first-class data attached to relevant assets/components. An imported transform may retain its original pool-scoped index. Derive encoding, alignment, placement, sizes, actual pointers, checksums, and relocations during export from current values and verified format rules. Do not cache those decisions or original offsets in Rete to force a match. Preserve unknown data explicitly while investigating its meaning.
- Develop needed converter-owned Godot assets alongside the exporter and OpenSpace/Model/Rete parity work. Shaders, components and engine-side functions may be committed and maintained now in a coherent support package with documented, tested interfaces. The former blanket deferral is removed; full package parity is not a prerequisite. Most AI engine functions can wait until converted GDScript tests need them. Godot output validates semantic understanding, and supported authored consumers may grow with it. Game/remaster projects own their authored game assets and depend on Astrolabe, even when packaged together. Godot reverse import remains optional.
- Design for a Godot developer in both the dehydrated committed project and the rehydrated project with converted content. Keep converter support, authored game work and generated assets clearly owned, with readable source, native extension points and one consistent project arrangement. Maintain support in one source location; version its interfaces with the exporter. Separate project initialization, support updates and content regeneration; preserve authored settings/files and unrelated generated levels. Keep game-derived content and caches local, while tracking authored Godot scenes/resources. Follow [Godot project structure and ownership](./docs/astrolabe/godot-project.md).
- Temporary harnesses must exercise the same exported resources and maintained support assets that consumers use; editor inspection/native animation seeking must validate content independently of preview bootstrap code. Diagnostic/report JSON is permitted; wrapping runtime-interpreted source tables in custom Resources does not satisfy native conversion.
- Keep virtual addresses, memory layout, and relocation generation at the OpenSpace import/export boundaries. Loading Rete or exporting Godot must not reconstruct SNA/relocation tables.
- Preserve unknown bytes explicitly. Opaque records are preservation placeholders; promote documented structures before reading their fields or traversing their pointers.
- OpenSpace loads one level at a time, with shared Fix/media packages. Bind Fix-to-level references within the active session; batch conversion may select levels sequentially. Do not cache level bindings globally on shared Fix assets.
- Store cross-package links as role URIs (`fix:/`, `level:/`, `texture:/`, `sound:/`) and mirror the game tree under one output root.
- PNG/WAV are mainly Godot output formats, not mandatory Rete storage. Choose information-preserving useful texture/audio representations and minimal necessary metadata; retain richer structured values in MessagePack when PNG/WAV are insufficient. OpenSpace export must rebuild without source-disc access, encoded-blob replay, or cached encoding/layout decisions. See [media representation](./docs/rete/rete-design.md#media-representation).
- Remove superseded production paths when replacing them. Backward compatibility with old CLI names, package layouts, and intermediate schemas is not a requirement.
- Restore working LZO compression/decompression, textures (CNT/GF), and standalone audio (APM/BNM) before the main level parser. Textures/audio come first to preserve their user-reported complete C# import capability, not because they represent level-file architecture. Use C# and local fixtures as regression references, corroborate interpretation through the reference hierarchy below, and prefer suitable existing crates for standard codecs. Defer level-dependent sound bindings until scene import. Exact historical LZO byte matching is a late fidelity task, distinct from early working compression.
- Defer the original Indeo AVI cutscenes until late in the port; plan FFmpeg conversion and actual playback validation on the pinned Godot version.
- Keep the Rust implementation independent of Unity and the reference projects.

## Reference authority

The original OpenSpace engine and its decompilation are the source of truth, followed by Raymap. **Raymap is usually the first practical reference to consult**, before investigating the engine directly. Keep the C# implementations and historical research notes as valuable regression/research evidence, but do not trust their interpretation fully or copy it without corroboration. Resolve conflicts against the engine/decompilation for the relevant build and record the evidence. See [reference authority and research workflow](./reference/README.md#reference-authority-and-research-workflow).

## Working rule

Work directly on `main`. This is a single-developer project: do not create branches unless Stephen asks, and do not push without being asked. Commit as you go, and run the gate at merge-point-sized steps.

## Validation and local data

Run `python3 tools/gate.py` before merging. Unsupported source calls get documented [stand-ins](./docs/astrolabe/stand-ins.md), never silent no-ops. Check new AI parser assumptions against live memory through Orrery.

Build with `cargo build --release --locked`. Existing commands are `python3 tools/test.py --offline` for synthetic checks and `python3 tools/test.py --local --offline` for the complete local corpus/Godot suite. The supervisor captures logs in ignored `TestResults/` and cleans child processes. Focused selection (`--area movement --local`), mandatory safeguards and exact release inventory (`--release`) are implemented with pinned nextest; `tools/coverage.py` collects a separate LLVM Rust coverage run. Native runtime, live comparison and BDD work remain in progress under [the dated comparison plan](./notes/realtime-comparison-plan.md). See [the testing guide](./docs/astrolabe/testing.md). `cargo fmt --check` and `cargo clippy --locked --all-targets -- -D warnings` check style/lints. The old .NET commands apply only inside the archived C# references.

Before adding or running a temporary native probe, read [the probe workflow](./docs/astrolabe/probe-workflow.md). Reuse Orrery's isolation and explicit display-bridge API for test binaries; check Godot harness syntax with an owned log path before expensive conversion. Concurrent workers need separate source, build, generated-output and evidence paths.

Reusable Model geometry and ModelInstance transforms/radiosity are separate assets. Preserve this boundary when milestone 6 expands scene traversal; tests/model_instances.rs checks shared geometry with independent placement and lighting through Rete, source fragments, and Godot. Rete schema and generated Godot paths remain provisional; explicit rename/identity checks prevent silently mismatched references. Preserve structured source coverage diagnostics through Rete and keep source VM observations in transient debug reports.

**Keep individual tests and each active development area's checks bounded and reasonably fast.** The former universal ten-minute whole-suite limit is removed. Development validation selects the affected area/dependencies plus mandatory safeguards against bypassing real conversion/gameplay; it need not run every unrelated test. Final release validation includes the full declared matrix and may take longer. Measure build, setup, test and cleanup time; enforce per-test/scenario deadlines and explicit suite budgets with cleanup reserved. A timeout is a failure. Preserve all release coverage when splitting large tests, report selection/exclusions, and do not omit required safeguards to obtain a pass. See the [selection and timing policy](./notes/realtime-comparison-plan.md#test-selection-and-timing-policy). The focused runner replaces the former 570-second cap with explicit per-test and per-selection budgets.

Use `disc/` for user-provided game files and `output/` for generated assets; both are ignored. Local format validation historically used `disc/Gamedata/World/Levels/astrolabe`. Preserve local game data and generated assets during repository maintenance.

Build validation from useful asset inspection and deliberate edits, through Rete save/load, asset/record reconstruction, and individual source-file parity, toward whole-package decompressed content and generated relocation parity. Exact pre-compression package parity remains a long-term requirement. The historical LZO encoder discrepancy is a separate final byte-fidelity gate and must not block Godot progress. Do not require complete package parity before implementing a useful asset. Runtime behavior and semantic checks complement byte comparison; Godot output has its own scene and asset quality checks. Original-engine tests are opportunistic, never a universal feature/milestone prerequisite. Use Raymap as a backup and source-informed checks where runtime/viewer coverage is unavailable; report those gaps explicitly. Pixel-perfect Godot output is a useful parity target, not an expected or universal requirement.

## Running the original engine and Raymap

The user supplied [`reference/hype-the-time-quest-lutris.json`](./reference/hype-the-time-quest-lutris.json) as the setup reference for running Hype under Lutris/Wine. It is a Lutris installer API export, not evidence of an already configured local installation. **The Python `hype` MCP harness remains available, but the new suite must not rely on it.** Use the native Rust **Orrery** controller for new original-game comparisons so typed OpenSpace observations can serve both its API and MCP surface. Its live MCP launch, save, physical input, selected AI inspection, screenshot and stop path was verified on 2026-09-23. Keep the runnable suite usable with an explicit pending original backend until those capabilities are connected to a reusable scenario and its assertions; a behavior scenario can pass on the original game independently of Godot. Preserve the private installation, saves and game-derived evidence. The Python harness and its earlier runs remain optional diagnostic references. The converter adapters must not depend on the controller. Read the [comparison plan](./notes/historical/plan-2026-10.md#original-engine-comparison-control) and [runtime guide](./reference/README.md#runtime-validation) before runtime work. Distinguish static/Rete-to-live data comparisons, single-backend behavior results, cross-engine comparisons, and acceptance of reconstructed packages.

**The game has a very slow intro.** The user supplied `reference/Savefile_EN.zip` to bypass it; use this as the first-choice runtime fixture. Preserve its `SaveGame0/` structure, verify the installed edition/language and actual save root, and record the reached scene/state. Archive integrity and loading into `manoir` were verified in earlier runs; verify the fixture and reached state in each new Orrery scenario. Use other chosen saves or targeted process-memory editing only when needed to reach a particular test state. Record the executable/build, fixture hash, save state or memory intervention, and the behavior being checked. Use interventions to reach the test state, not to repair exported asset data in memory and mask a reconstruction bug. Preserve original game data and saves; exercise generated data in a test installation/copy.

Raymap is an independent parser and visual reference. The user has found its web version useful and expects it may be able to load local OpenSpace level files; verify that workflow before relying on it for generated levels. Prefer the web viewer or local WebGL snapshot described in the reference README. **The user does not use the Unity Editor; do not make Unity installation a prerequisite.** Raymap is the practical backup when original-engine tests cannot run, within its supported features. Supplement it with engine/decompilation-informed expectations and report unverified gameplay behavior; do not block all progress on original-engine availability. A disposable Godot orbit/contact-sheet/audio-mixer harness is implemented. Consult the current [runtime evidence](./notes/implementation-progress.md#runtime-reference-status) for both harnesses and their limits.
